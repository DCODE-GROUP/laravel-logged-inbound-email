# Rebuild the package on spatie/package-skeleton-laravel conventions

The package currently registers itself through a hand-rolled `ServiceProvider` (manual `mergeConfigFrom`, manual `publishes`, manual route group). Since this fork now needs to publish a config file, publishable migration stubs, and register models/commands as the package grows, we're rebuilding the service provider on `spatie/laravel-package-tools`'s `PackageServiceProvider` and adopting the wider `spatie/package-skeleton-laravel` project conventions (Testbench `workbench/` for local development, its CI workflow shape, `CHANGELOG.md`) as if the package had started on that skeleton, rather than incrementally bolting migration-publishing logic onto the existing hand-rolled provider. This is a larger one-time restructuring cost, but it's the same skeleton a large share of the Laravel package ecosystem already uses, which matters for anyone else picking up this fork later.
