# Attachments stored via a dedicated model and configurable disk, not a media library

`trady`'s equivalent model stores attachments through `spatie/laravel-medialibrary`, which brings its own tables, conventions, and a hard dependency. We instead introduce a package-owned `InboundEmailAttachment` model (`filename`, `disk`, `path`, `content_type`, `size`) that writes files to a single disk named in package config, with no third-party media dependency. This keeps the package's dependency footprint aligned with what it already has (it previously carried attachments as in-memory base64 inside `InboundMessage`), and avoids imposing an opinionated media-management system on every consumer for what is, at this scope, just "put the file somewhere and remember where." If a consumer later needs media-library-grade features (conversions, responsive images, etc.), that's an application-level concern layered on top, not something this package needs to own.
